## 3. Application Flow and Screen Details

The application flow is managed by `expo-router`. The main entry point is `app/_layout.tsx`, which sets up the global providers (`AuthProvider`, `ThemeProvider`) and the main navigation stack.

**Screen Flow:**

1.  **Initial Load / Splash Screen:** The app starts, and `useFrameworkReady` hook likely handles font loading and other initial setup.
2.  **Authentication Check (`AuthProvider`):**
    *   The `AuthProvider` checks for a stored session (token and user data) in `SecureStore`.
    *   If a session exists, the user is authenticated and navigated to the main dashboard.
    *   If no session exists, the user is presented with the **Login Screen**.
3.  **Login Screen (`app/auth/login.tsx`):**
    *   **Purpose:** Allows users to sign in, navigate to registration, or continue as a guest.
    *   **Components:** `TextInput` for email/password, `TouchableOpacity` for buttons.
    *   **Navigation:**
        *   On successful login (`login` function from `AuthContext`), navigates to `/(tabs)`.
        *   `Link` to `/auth/register` for new users.
        *   `TouchableOpacity` to `/auth/forgot-password`.
        *   `continueAsGuest` function also navigates to `/(tabs)`.
    *   **State/API:**
        *   Uses `useAuth` context for `login`, `continueAsGuest`, `isLoading`, and `error` state.
        *   The `login` function in `AuthContext` is currently a mock but is intended to make an API call.
4.  **Tab Navigator (`app/(tabs)/_layout.tsx`):**
    *   This is the main layout for authenticated users, containing four tabs: Home, Learn, Progress, and Profile.
5.  **Home Screen (`app/(tabs)/index.tsx`):**
    *   **Purpose:** The main dashboard, displaying user stats, quick actions, recent activity, and achievements.
    *   **Components:** `ScrollView`, `LinearGradient`, `GuestBanner`, and various custom components.
    *   **Navigation:** Quick actions navigate to other tabs (`/learn`, `/progress`).
    *   **State/API:**
        *   Fetches and displays a list of "todos" from the `todos` table in Supabase.
        *   Uses `useAuth` to get user information.
        *   The `PulsingActionButton` is likely intended to initiate the core "solver" flow.

## 4. Supabase Integration

Supabase is deeply integrated for authentication, database operations, and serverless functions.

- **Configuration (`lib/supabase.ts`):**
    *   The Supabase client is initialized here using environment variables for the URL and anon key.
    *   It's configured to use `AsyncStorage` for session persistence in React Native.

- **Authentication (`contexts/AuthContext.tsx`):**
    *   The `AuthProvider` manages the user's authentication state.
    *   The `login`, `register`, and `logout` functions are placeholders for Supabase auth calls.
    *   The `logout` function already includes a call to `supabase.auth.signOut()`.

- **Database (`app/(tabs)/index.tsx`):**
    *   The Home screen directly queries the `todos` table using `supabase.from('todos').select('*')`.

- **Serverless Functions (`supabase/functions/submit-problem/index.ts`):**
    *   This Deno-based function handles problem submissions.
    *   It receives problem data (text, image, etc.), creates a record in the `problem_submissions` table, and then calls the Google Gemini API for analysis.
    *   The result from Gemini is then used to update the submission record in Supabase.

- **Hooks (`hooks/useSecureSession.ts`):**
    *   This hook manages a "secure session" by interacting with a `learning_sessions` table in Supabase. It creates, retrieves, and ends sessions, providing a layer of security and tracking for user activity.

## 5. Overall Application Architecture

- **Folder Structure:** The project follows a standard React Native/Expo structure with clear separation of concerns:
    *   `app/`: Routing and screens (managed by `expo-router`).
    *   `components/`: Reusable UI components.
    *   `constants/`: Application-wide constants.
    *   `contexts/`: Global state management (e.g., `AuthContext`).
    *   `hooks/`: Reusable logic and side effects.
    *   `lib/`: Core libraries and services (e.g., `supabase.ts`).
    *   `supabase/`: Backend-as-a-Service configuration, including database migrations and serverless functions.
    *   `types/`: TypeScript type definitions.

- **Key Architectural Points:**
    *   **State Management:** Primarily handled through React Context (`AuthContext`, `ThemeContext`).
    *   **Navigation:** File-based routing with `expo-router`.
    *   **Backend:** Supabase provides the core backend infrastructure.
    *   **AI Integration:** The `submit-problem` Supabase function integrates with the Google Gemini API.

- **Areas for AWS Integration:**
    *   **API Gateway & Lambda:** While Supabase Functions are used, more complex or high-volume backend logic could be offloaded to AWS Lambda functions, exposed via API Gateway. This would be particularly relevant for:
        *   Custom business logic that doesn't fit the Supabase model.
        *   Integrating with other AWS services.
    *   **S3 for Media Storage:** The `submit-problem` function currently seems to handle image data as a string (`image_data`). For a scalable solution, images and other media should be uploaded directly from the client to an S3 bucket. The Supabase function would then receive the S3 object key instead of the full image data.
    *   **Authentication:** While Supabase handles auth, a more complex system might involve AWS Cognito, especially if integration with other enterprise systems is required.

## 6. Backend Architect Role Definition

The **Backend Architect** will be the central authority for all backend integration tasks. Your responsibilities will include:

*   **Designing and Managing AWS Infrastructure:**
    *   Provisioning and configuring necessary AWS services (API Gateway, Lambda, S3, Cognito, etc.).
    *   Ensuring the AWS infrastructure is scalable, secure, and cost-effective.
*   **Connecting Front-end to Backend:**
    *   Defining and documenting the API contracts between the front-end and the AWS backend.
    *   Working with the front-end team to ensure secure and efficient communication.
*   **Handling Authentication and API Security:**
    *   Implementing robust authentication and authorization mechanisms.
    *   Securing all API endpoints and protecting sensitive data.
*   **Optimizing Communication:**
    *   Ensuring low-latency communication between the UI, Supabase, and AWS services.
    *   Implementing caching strategies where appropriate.
